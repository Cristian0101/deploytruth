# DeployTruth v0.1.0

First public release of DeployTruth, a read-only tool for verifying that declared deployment
topology matches observed provider and runtime state.

## What it does

DeployTruth checks relationships across local Git, GitHub, Vercel, runtime attestation, and
Supabase. It produces one normalized PASS, WARN, or FAIL report and preserves UNKNOWN when the
required evidence is unavailable.

## Highlights

- Detects source-to-deployment and deployment-to-runtime SHA mismatches without blaming healthy
  relationships.
- Verifies runtime-to-database identity and compares repository migrations with applied Supabase
  migrations.
- Includes a private, loopback-only visual Truth Map with a factual evidence Inspector.
- Stores local report history and performs semantic run comparisons through `history` and `diff`.
- Ships a self-contained GitHub Action with Job Summary output, machine-readable outputs, and a
  sanitized evidence bundle.
- Uses read-only provider transports, secret-safe reports, and no product telemetry by default.

## Install

Requires Node.js 22 or later.

```bash
npx deploytruth --help
```

or:

```bash
npm install -g deploytruth
deploytruth --help
```

## GitHub Action

```yaml
- uses: Cristian0101/deploytruth@v0
  with:
    environment: production
```

Pin `Cristian0101/deploytruth@v0.1.0` when an immutable Action reference is preferred.

## Security model

Credentials are supplied only through environment variables. Provider access is read-only,
database inspection runs fixed queries in rolled-back read-only transactions, the web report binds
only to loopback, and evidence artifacts are allowlisted and sanitized. Report vulnerabilities
through GitHub private vulnerability reporting, never a public issue.

## Known limitations

- macOS and Linux are certified; Windows is not yet certified.
- DeployTruth is pre-1.0. Inputs, outputs, configuration, and report schema may change.
- Provider support in v0.1.0 is GitHub, Vercel, and Supabase.
- Live checks require the user's own provider credentials and, for runtime identity, an explicit
  application attestation endpoint.
